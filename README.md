# بن ثابت — تطبيق الحسابات التجارية

تطبيق Android عربي باتجاه RTL لإدارة حسابات العملاء والموردين والديون والمدفوعات بعملتين منفصلتين: الريال السعودي (SAR) والريال اليمني (YER).

## محتويات المشروع

- Flutter 3.50.1 / Dart 3.14.
- قاعدة بيانات SQLCipher مشفرة، ومفتاحها محفوظ في Android Keystore عبر `flutter_secure_storage`.
- رمز PIN محلي مشتق بـ PBKDF2-HMAC-SHA256، وقفل تلقائي عند مغادرة التطبيق، وبصمة عند دعم الجهاز.
- منع لقطات الشاشة وتسجيل الشاشة ومعاينات التطبيقات الحديثة على Android عبر `FLAG_SECURE`.
- العملاء بأرقام 100001–199999، والموردون بأرقام تبدأ من 200001؛ الرقم فريد ولا يعاد استخدامه.
- ملفات العملاء والموردين قابلة للتعديل، مع حفظ سجل تدقيق للتعديل والأرشفة.
- حركات الديون والدفعات؛ قيود قاعدة البيانات تمنع أن يصبح رصيد أي طرف سالبًا عند الإضافة أو التعديل أو الأرشفة المنطقية للعملية.
- فصل تام لأرصدة SAR وYER، دون تحويل أو جمع تلقائي بينهما.
- مصروفات وإيرادات عامة، بحث متعدد الحقول، سجل العمليات، وأرشفة الحسابات مع الاحتفاظ بالحركات.
- مشاركة كشف الحساب كنص من شاشة الحساب.
- هوية المحل وشعاره، وأيقونة تطبيق مستقلة نظيفة مرسومة بأسلوب Material، وأيقونات واجهة Material واضحة بدل الرموز التعبيرية.
- نهاري/ليلي/حسب النظام، تلميحات محلية قصيرة، وواجهات عربية متجاوبة.
- نسخ محلي أسبوعي مشفر مع الاحتفاظ بآخر 7 نسخ، وتصدير ملف محمول `.bthbackup` مشفر بكلمة مرور ومشاركته من قائمة Android (WhatsApp أو Drive عند توفر التطبيق).
- الاستعادة تتحقق من سلامة الملف والقاعدة، وتستخدم سجل استعادة لاسترجاع النسخة السابقة عند الانقطاع أثناء تبديل قاعدة البيانات.
- GitHub Actions يشغل فحص SQLite، ثم `flutter analyze` و`flutter test` وبناء APK.

## قيود مهمة يجب معرفتها

- النسخ الأسبوعي المحلي داخل مجلد التطبيق؛ **يُحذف عند إزالة التطبيق أو مسح بياناته**. لاستعادة البيانات بعد الحذف أو تغيير الهاتف، صدّر ملف `.bthbackup` واحفظه خارج التطبيق (مثل واتساب أو Google Drive). مشاركة الملف تتم باختيار المستخدم ولا يرسله التطبيق تلقائيًا.
- لا يوجد تكامل Google Drive API مباشر أو رفع سحابي تلقائي مجدول في هذه النسخة. يمكن اختيار Google Drive من نافذة مشاركة Android عند توفره.
- نظام Android قد يؤخر مهام الخلفية الأسبوعية حسب الطاقة وسياسات النظام؛ لذلك يوجد خيار إنشاء نسخة فورية يدويًا.
- عبارة مرور النسخة المحمولة يجب أن تكون من 12 إلى 128 حرفًا. لا تحفظ كلمة المرور مع ملف النسخة.
- استعادة النسخة تستبدل قاعدة البيانات الحالية بعد التحقق منها؛ يجب إنشاء نسخة حالية أولًا إن كانت تحتوي بيانات جديدة.
- أرشفة الحساب تحفظ جميع عملياته كما هي وتمنع إضافة ديون جديدة؛ لا تختصر السجل القديم إلى قيد رصيد افتتاحي واحد. يمكن تسوية الرصيد ثم إعادة فتح الحساب.
- لا تتضمن هذه النسخة إدارة مخزون أو فواتير بيع/شراء أو حساب ربح محاسبي كامل أو تصدير PDF/Excel أو تحويل عملات بسعر صرف. كشف الحساب يمكن مشاركته كنص.
- أرقام SAR وYER تحفظ بوحدات صحيحة بدقة منزلتين عشريتين، ولا تُجمع العملات معًا.

## البناء محليًا

المتطلبات: Flutter 3.50.1 / Dart 3.14 أو أحدث متوافق، Java 17، Android SDK.

```bash
bash tool/prepare_android.sh
python3 tool/verify_schema.py
flutter pub get
dart run flutter_launcher_icons
flutter analyze
flutter test
flutter build apk --release
```

APK: `build/app/outputs/flutter-apk/app-release.apk`

## GitHub Actions

ارفع محتويات المشروع إلى مستودع GitHub على الفرع `main`. سيعمل `.github/workflows/android.yml` عند الدفع أو فتح Pull Request أو تشغيله يدويًا. يُنشئ ملفات Android، ويفحص قيود قاعدة البيانات، ويحلل Dart، ويشغل الاختبارات، ثم يبني APK ويرفعه كـ Artifact.

## حالة التحقق الحالية

تم فحص SQL DDL والقيود المالية باستخدام SQLite في بيئة المراجعة، وفحص صياغة سكربت Android وملف GitHub Actions. لم يكن Flutter/Dart SDK مثبتًا في بيئة المراجعة؛ لذلك لم يتم تشغيل `flutter analyze` أو `flutter test` أو بناء APK محليًا. يجب انتظار نجاح CI ثم اختبار الاستعادة والبصمة ومشاركة الملف على جهاز Android فعلي قبل استخدام التطبيق لحسابات حقيقية.
